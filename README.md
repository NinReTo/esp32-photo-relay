# esp32-photo-relay

Загрузка фото с телефона на ПК через ESP32 — без SD-карты и без записи во флеш-память платы.

## Что это

ESP32 здесь — **труба, а не хранилище**. Плата подключается к домашнему Wi-Fi и поднимает
веб-страницу с формой загрузки. Вы открываете её в браузере телефона, снимаете или выбираете
фото и нажимаете «Отправить». Плата принимает файл по кускам и каждый кусок сразу пересылает
на ПК по TCP. На самой плате ничего не сохраняется, поэтому размер фото не ограничен её памятью.

Зачем это нужно: быстро перекинуть фото с телефона на компьютер, когда под рукой есть только
ESP32 без SD-карты, а ставить на телефон отдельные приложения не хочется. Заодно это
наглядный учебный пример потоковой пересылки данных на микроконтроллере.

## Архитектура

```
+-----------+   HTTP POST    +-----------+      TCP       +-------------+
|  Телефон  |  (multipart)   |   ESP32   |   порт 5050    |  Приёмник   |
| (браузер) | -------------> | веб-сервер| -------------> |   на ПК     | ---> received/фото.jpg
+-----------+   порт 80      +-----------+                +-------------+
                              ничего не                    receiver.c
                              сохраняет
```

Протокол между платой и приёмником предельно простой:

1. плата отправляет имя файла и символ перевода строки `\n`;
2. дальше идёт содержимое файла как есть;
3. плата закрывает соединение — это признак конца файла.

Структура репозитория:

```
esp32-photo-relay/
  firmware/esp32_photo_relay/esp32_photo_relay.ino   прошивка ESP32
  receiver/receiver.c                                приёмник на ПК
  receiver/Makefile                                  сборка приёмника на Linux/macOS
```

## Что нужно

**Оборудование**

- любая плата ESP32 с Wi-Fi (например, ESP32 DevKit) и USB-кабель для прошивки;
- телефон и ПК, подключённые к той же домашней сети, что и плата.

**Программы**

- [Arduino IDE](https://www.arduino.cc/en/software) с установленным ядром **esp32**
  (Boards Manager → `esp32` от Espressif Systems). Сторонние библиотеки не нужны:
  используются только встроенные `WiFi.h` и `WebServer.h`;
- компилятор C на ПК: `gcc` (Linux/macOS), MinGW или MSVC (Windows).

## Настройка

### 1. Узнайте IP-адрес ПК в локальной сети

| Система | Команда    | Что искать                                     |
|---------|------------|------------------------------------------------|
| Windows | `ipconfig` | строку «IPv4-адрес» у активного адаптера       |
| Linux   | `ip a`     | строку `inet` у активного интерфейса           |
| macOS   | `ifconfig` | строку `inet` у активного интерфейса           |

Адрес обычно выглядит как `192.168.x.x`. Удобно закрепить его за ПК в настройках роутера,
чтобы он не менялся после перезагрузки.

### 2. Поменяйте переменные в прошивке

Откройте `firmware/esp32_photo_relay/esp32_photo_relay.ino` и задайте в начале файла:

| Переменная | Значение                                                          |
|------------|-------------------------------------------------------------------|
| `ssid`     | название вашей сети Wi-Fi (только 2,4 ГГц — 5 ГГц ESP32 не видит) |
| `password` | пароль от сети Wi-Fi                                              |
| `pcHost`   | IP-адрес ПК из предыдущего шага                                   |
| `pcPort`   | порт приёмника, по умолчанию `5050`                               |

> Не отправляйте в публичный репозиторий файл с настоящим паролем от Wi-Fi.

## Сборка и запуск

### Прошивка ESP32

1. Откройте `esp32_photo_relay.ino` в Arduino IDE.
2. Выберите плату: **Tools → Board → esp32 → ESP32 Dev Module** (или вашу модель).
3. Выберите порт: **Tools → Port**.
4. Нажмите **Upload**. Если загрузка не начинается, удерживайте кнопку **BOOT** на плате.
5. Откройте **Serial Monitor** на скорости **115200** бод.

### Сборка приёмника

**Linux / macOS**

```bash
cd receiver
make            # то же самое, что: gcc receiver.c -o receiver
./receiver
```

**Windows, MinGW**

```bash
cd receiver
gcc receiver.c -o receiver.exe -lws2_32
receiver.exe
```

**Windows, MSVC** (в окне «Developer Command Prompt for VS»)

```bash
cd receiver
cl /utf-8 receiver.c ws2_32.lib
receiver.exe
```

Ключ `/utf-8` нужен, чтобы русские сообщения правильно отображались в консоли.

Порт можно задать при запуске: `receiver 6000`. Тогда тот же порт нужно указать
в `pcPort` в прошивке.

При первом запуске на Windows брандмауэр спросит, разрешить ли программе доступ к сети —
разрешите для **частных** сетей. На Linux при включённом брандмауэре откройте порт,
например: `sudo ufw allow from 192.168.0.0/16 to any port 5050 proto tcp`.

### Порядок действий

1. **Запустите приёмник на ПК.** В консоли появится «Ожидание подключения...».
2. **Включите ESP32.** В Serial Monitor появится IP-адрес платы и ссылка вида `http://192.168.1.57/`.
3. **Откройте эту ссылку на телефоне**, сделайте снимок или выберите фото и нажмите «Отправить».
4. Фото появится на ПК в папке `receiver/received/`, а приёмник выведет имя, путь и размер файла.

Полезно знать:

- если файл с таким именем уже есть, приёмник не затирает его, а добавляет номер: `image_1.jpg`;
- если имя файла пустое или небезопасное, подставляется имя по дате и времени:
  `photo_20261110_200512.jpg`;
- если загрузка оборвалась на середине, на ПК может остаться неполный файл. Протокол не
  передаёт размер, поэтому приёмник не отличит его от целого — ориентируйтесь на сообщение
  об ошибке на странице в телефоне и в Serial Monitor.

## Безопасность

Это учебный проект, и защиты в нём нет:

- **нет аутентификации** — отправить файл может любой, кто находится в той же сети;
- **нет шифрования** — фото идут по сети в открытом виде (обычные HTTP и TCP).

Поэтому:

- используйте проект **только в домашней доверенной сети**;
- **не открывайте порты наружу в интернет**: не настраивайте проброс портов (port forwarding)
  на роутере ни для платы (порт 80), ни для приёмника (порт 5050);
- не запускайте приёмник в общественных и гостевых сетях;
- закрывайте приёмник, когда он не нужен.

Приёмник очищает присланное имя файла (убирает слэши, обратные слэши и `..`) и пишет только
в папку `received/`, но это защита от случайностей, а не от целенаправленной атаки.
