# esp32-photo-relay

Загрузка фото с телефона на ПК через ESP32 — без SD-карты и без записи во флеш-память платы.

## Что это

ESP32 здесь — **труба, а не хранилище**. Плата подключается к домашнему Wi-Fi и поднимает
веб-страницу с формой загрузки. Вы открываете её в браузере телефона, снимаете или выбираете
фото и нажимаете «Отправить». Плата принимает файл по кускам и каждый кусок сразу пересылает
на ПК по TCP. На самой плате ничего не сохраняется, поэтому размер фото не ограничен её памятью.

Зачем это нужно: быстро перекинуть фото с телефона на компьютер, когда под рукой есть только
ESP32 без SD-карты, а ставить на телефон отдельные приложения не хочется. Заодно это
наглядный учебный пример потоковой пересылки данных на микроконтроллере.

На ПК работает **оконное приложение** (Windows 10/11 и Linux): оно показывает, подключена ли
плата, настраивает её Wi-Fi по USB, принимает фото и показывает телефоны, которые ими
пользовались. Править код прошивки для настройки не нужно.

## Архитектура

```
+-----------+   HTTP POST    +-----------+      TCP       +----------------+
|  Телефон  |  (multipart)   |   ESP32   |   порт 5050    |  Приложение    |
| (браузер) | -------------> | веб-сервер| -------------> |    на ПК       | ---> received/фото.jpg
+-----------+   порт 80      +-----------+                +----------------+
                              ничего не         USB              |
                              сохраняет   <----------------------+
                                           настройки и состояние
```

Протокол передачи фото между платой и ПК предельно простой:

1. плата отправляет имя файла и символ перевода строки `\n`;
2. дальше идёт содержимое файла как есть;
3. плата закрывает соединение — это признак конца файла.

По USB (115200 бод) приложение отправляет плате короткие текстовые команды: `STATUS`,
`WIFI <сеть> <пароль>`, `PC <адрес> <порт>`. Плата хранит настройки в своей памяти настроек
и после перезагрузки подключается сама. Полное описание команд — в начале файла прошивки.

Структура репозитория:

```
esp32-photo-relay/
  firmware/esp32_photo_relay/esp32_photo_relay.ino   прошивка ESP32
  app/                                               оконное приложение для ПК (Rust)
  receiver/receiver.c                                консольный приёмник (запасной вариант, C)
  receiver/Makefile                                  сборка консольного приёмника на Linux/macOS
```

## Что нужно

**Оборудование**

- любая плата ESP32 с Wi-Fi (например, ESP32 DevKit) и USB-кабель с линиями данных;
- телефон и ПК, подключённые к той же домашней сети, что и плата.

**Программы**

- [Arduino IDE](https://www.arduino.cc/en/software) с установленным ядром **esp32**
  (Boards Manager → `esp32` от Espressif Systems) — чтобы один раз прошить плату.
  Сторонние библиотеки не нужны: используются только встроенные `WiFi.h`, `WebServer.h`
  и `Preferences.h`;
- для сборки приложения — [Rust](https://rustup.rs/) (на Windows вместе с ним ставятся
  Build Tools for Visual Studio);
- драйвер USB-переходника платы (CP210x или CH340), если система не поставила его сама.

## Быстрый старт

### 1. Прошейте плату

1. Откройте `firmware/esp32_photo_relay/esp32_photo_relay.ino` в Arduino IDE.
2. Выберите плату: **Tools → Board → esp32 → ESP32 Dev Module** (или вашу модель).
3. Выберите порт: **Tools → Port**.
4. Нажмите **Upload**. Если загрузка не начинается, удерживайте кнопку **BOOT** на плате.
5. Закройте Serial Monitor, если открывали: порт может занимать только одна программа.

Менять что-либо в коде не нужно — сеть и адрес ПК задаются из приложения.

### 2. Соберите и запустите приложение

```bash
cd app
cargo run --release
```

Готовая программа лежит в `app/target/release/` (`photo-relay-app.exe` на Windows,
`photo-relay-app` на Linux) — её можно скопировать куда удобно и запускать двойным щелчком.
Собранные программы для Windows и Linux также прикладываются к каждому запуску проверки
на GitHub: вкладка **Actions** → последний запуск → **Artifacts**.

**Linux.** Перед сборкой может понадобиться поставить библиотеки для окон, а для доступа
к USB-порту — добавить себя в группу `dialout` и перезайти в систему:

```bash
sudo apt install build-essential pkg-config libxkbcommon-dev libwayland-dev libgl1-mesa-dev
sudo usermod -aG dialout $USER
```

**Windows.** При первом запуске брандмауэр спросит, разрешить ли программе доступ к сети —
разрешите для **частных** сетей, иначе плата не сможет передать фото.

### 3. Настройте плату в окне приложения

1. Подключите плату USB-кабелем. В разделе **«Плата»** выберите порт и нажмите **«Подключить»** —
   индикатор станет зелёным.
2. В разделе **«Wi-Fi платы»** проверьте название сети (подставляется сеть ПК), введите пароль
   и нажмите **«Сохранить на плату»**. Вместе с сетью плате передаётся адрес этого ПК.
3. Когда плата подключится к Wi-Fi, в окне появится ссылка вида `http://192.168.1.57/`.
4. Откройте ссылку на телефоне, сделайте снимок или выберите фото и нажмите «Отправить».
5. Фото появится в разделе **«Принятые фото»** и в папке `received` рядом с программой.

После настройки USB-кабель нужен плате только для питания: её можно включить в любую
зарядку, а приложение продолжит принимать фото. Состояние платы и список телефонов видны,
пока плата подключена к ПК по USB.

### Что показывает окно

| Раздел           | Что в нём                                                                |
|------------------|--------------------------------------------------------------------------|
| Плата            | подключена ли плата по USB, выбор порта                                  |
| Wi-Fi платы      | к какой сети подключена, IP-адрес, уровень сигнала, ссылка для телефона  |
| Этот компьютер   | IP-адрес и сеть ПК, работает ли приём фото                               |
| Телефоны         | кто открывал страницу платы: адрес, когда, сколько фото отправил         |
| Принятые фото    | список принятых файлов и кнопка открытия папки                           |
| Журнал платы     | сообщения прошивки — пригодится, если что-то не работает                 |

В списке телефонов — устройства, которые обращались к странице платы с момента её включения
(до восьми последних). Плата не видит всех участников сети Wi-Fi, только своих посетителей.

Полезно знать:

- если файл с таким именем уже есть, он не затирается — к имени добавляется номер: `image_1.jpg`;
- если имя файла пустое или небезопасное, подставляется имя по дате и времени:
  `photo_20261110_200512.jpg`;
- если загрузка оборвалась на середине, на ПК может остаться неполный файл. Протокол не
  передаёт размер, поэтому ПК не отличит его от целого — ориентируйтесь на сообщение
  об ошибке на странице в телефоне.

## Если что-то не работает

| Что видно                                   | Что проверить                                                                 |
|---------------------------------------------|-------------------------------------------------------------------------------|
| «Порты не найдены»                          | кабель (бывают только для зарядки), драйвер CP210x/CH340                      |
| «Не удалось открыть порт»                   | порт занят Arduino IDE (Serial Monitor); на Linux — группа `dialout`          |
| «Устройство не отвечает»                    | выбран не тот порт или на плате старая прошивка                               |
| «Подключается к…» и дальше ничего           | название сети и пароль; сеть должна быть 2,4 ГГц                              |
| «Плата настроена слать фото не на этот ПК»  | нажмите «Передать плате адрес этого ПК» (адрес ПК мог смениться)              |
| В окне показан странный IP-адрес ПК         | включён VPN или виртуальная сеть — отключите их, адрес должен быть вида `192.168.x.x` |
| На телефоне «не удалось подключиться к ПК»  | приложение запущено, брандмауэр разрешает порт 5050, ПК и плата в одной сети  |
| «Приём фото не работает»                    | порт 5050 занят — закройте второй экземпляр приложения или `receiver`         |

## Без приложения: настройка в коде и консольный приёмник

Этот способ оставлен как запасной и как пример на чистом C.

**Настройки в прошивке.** В начале `.ino` файла можно вписать значения по умолчанию — они
действуют, пока приложение не передало свои:

| Переменная | Значение                                                          |
|------------|-------------------------------------------------------------------|
| `ssid`     | название вашей сети Wi-Fi (только 2,4 ГГц — 5 ГГц ESP32 не видит) |
| `password` | пароль от сети Wi-Fi                                              |
| `pcHost`   | IP-адрес ПК (`ipconfig` на Windows, `ip a` на Linux)              |
| `pcPort`   | порт приёмника, по умолчанию `5050`                               |

> Не отправляйте в публичный репозиторий файл с настоящим паролем от Wi-Fi.

IP-адрес платы и ссылку для телефона прошивка печатает в Serial Monitor (115200 бод).

**Консольный приёмник** `receiver/receiver.c` делает то же, что приём фото в приложении.
Запускать одновременно с приложением нельзя: оба занимают порт 5050.

Linux / macOS:

```bash
cd receiver
make            # то же самое, что: gcc receiver.c -o receiver
./receiver
```

Windows, MinGW:

```bash
cd receiver
gcc receiver.c -o receiver.exe -lws2_32
receiver.exe
```

Windows, MSVC (в окне «Developer Command Prompt for VS»):

```bash
cd receiver
cl /utf-8 receiver.c ws2_32.lib
receiver.exe
```

Ключ `/utf-8` нужен, чтобы русские сообщения правильно отображались в консоли.
Порт можно задать при запуске: `receiver 6000` — тогда тот же порт укажите в `pcPort`.

## Безопасность

Это учебный проект, и защиты в нём нет:

- **нет аутентификации** — отправить файл может любой, кто находится в той же сети;
- **нет шифрования** — фото идут по сети в открытом виде (обычные HTTP и TCP);
- **пароль от Wi-Fi хранится на плате в открытом виде** — в её памяти настроек. Тот, у кого
  есть плата и USB-кабель, может его прочитать. Перед тем как отдать плату, сотрите её память
  (Arduino IDE: **Tools → Erase All Flash Before Sketch Upload → Enabled** и прошить заново).

Поэтому:

- используйте проект **только в домашней доверенной сети**;
- **не открывайте порты наружу в интернет**: не настраивайте проброс портов (port forwarding)
  на роутере ни для платы (порт 80), ни для ПК (порт 5050);
- не запускайте приложение и приёмник в общественных и гостевых сетях;
- закрывайте приложение, когда оно не нужно.

Присланное имя файла очищается (убираются слэши, обратные слэши и `..`), запись идёт только
в папку `received`, но это защита от случайностей, а не от целенаправленной атаки.
